# Controls/ — Python HLC Flight Scripts (Mode C)

This directory contains Python scripts that use `cflib` to fly the Crazyflie via the
High-Level Commander (HLC). These are **Mode C** — pre-generated Poly4D trajectories
uploaded once to drone onboard memory, then executed autonomously at ~100 Hz.

**Python environment**: always use `~/.pyenv/versions/flying_robots/bin/python` (not system python3).

## Key scripts

| Script | What it does |
|--------|-------------|
| `run_spline_circle.py` | Circle trajectory (r=0.30m, 8 segments, 1.309s each, 10.47s/lap) |
| `run_spline_figure8.py` | Figure-8 trajectory via HLC |
| `autonomous_sequence_high_level.py` | Full sequence: takeoff → figure-8 → land |
| `plot_trajectories.py` | Plots Poly4D trajectories without flying (validation) |
| `minimal_hover.py` | Minimal hover test (development reference) |
| `simple_high_level_commands.py` | HLC API examples |
| `diagnose_sensors.py` | Check Flow Deck + Multi-ranger readings |
| `check_decks.py` | Verify which decks are attached |

## How Poly4D trajectories work

1. **Generate** coefficients in Rust:
   ```bash
   cargo run --release --bin export_poly4d        # circle
   cargo run --release --bin export_poly4d figure8
   # stdout: Python list of [duration, cx0..cx7, cy0..cy7, cz0..cz7, cyaw0..cyaw7]
   ```

2. **Paste** the output into the Python script as `circle_poly4d = [...]`

3. **Fly**:
   ```bash
   ~/.pyenv/versions/flying_robots/bin/python run_spline_circle.py
   ~/.pyenv/versions/flying_robots/bin/python run_spline_circle.py --laps 2
   ~/.pyenv/versions/flying_robots/bin/python run_spline_circle.py --controller 2  # Mellinger fallback
   ```

## run_spline_circle.py key config

```python
DEFAULT_URI = "radio://0/80/2M/E7E7E7E7E7"
HOVER_HEIGHT = 0.5    # m
SPEED_SCALE = 0.5     # <1 = slower (0.5 = half planned speed → 20.94s/lap)
KALMAN_THRESH = 0.0025
```

**Controller**: `--controller 6` = OOT Rust geometric (default, requires flashed firmware),
`--controller 2` = Mellinger (fallback, always available).

## Poly4D format (33 columns per segment)

```
[duration, cx0, cx1, cx2, cx3, cx4, cx5, cx6, cx7,   # x (degree 7, physical time)
           cy0, cy1, cy2, cy3, cy4, cy5, cy6, cy7,   # y
           cz0, cz1, cz2, cz3, cz4, cz5, cz6, cz7,  # z (constant altitude)
           cyaw0..cyaw7]                               # yaw (constant heading)
```

Coefficients are in **physical time** [m, m/s, m/s², ...] at t=0.
Generated by `to_hermite_phys7()` in `src/bin/export_poly4d.rs` — degree-8 spline →
Hermite boundary matching → degree-7 C3-continuous physical-time polynomial.

## Validation without flying

```bash
~/.pyenv/versions/flying_robots/bin/python plot_trajectories.py
```
Evaluates Poly4D at 1000 points, plots XY path + position/speed/accel vs time.
Check: smooth curves, correct start/end, no velocity spikes at segment junctions.

## Pre-flight for Mode C

1. Firmware must have OOT controller: `cd flying_drone_stack/firmware_app && make cload`
2. Drone powered on, radio connected
3. Place on textured floor

## Difference from Mode B (Rust live full-state)

| | Mode B (Rust) | Mode C (Python HLC) |
|---|---|---|
| Evaluation | Laptop, real-time | Drone onboard, 100 Hz |
| Radio during flight | Required (25 Hz) | Not required after start |
| Trajectory degree | 8 (full) | 7 (Hermite-converted) |
| Feedforward | pos+vel+acc+quat+ω | pos+vel+acc (from Poly4D) |
| Radio dropout | Drone stops | Drone continues |
