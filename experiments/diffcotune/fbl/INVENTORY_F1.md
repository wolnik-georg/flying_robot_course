## 1. How frsim runs FBL

- **Firmware code through the bindings, no Python copy.** `simulator/frsim/controllers.py:9-12`: all five controllers run `controllerOmarIndi` from `cffirmware`; FBL is the branch `fbl.en = 1` (`controllers.py:128`). Source of the branch: `simulator/_build/crazyflie-firmware/src/modules/src/controller/controller_omar_indi.c:129-300` (`controllerOmarFbl`), `fbl_law.c`, `fbl_residual.c`, `fbl_nn_weights.c` in `src/modules/src/`.
- **Which firmware:** `simulator/firmware/README.md`: Bitcraze crazyflie-firmware `83aa19ed` + patch `crazyflie-firmware-sim.patch` ("the working-tree changes of the FBL firmware tree"). The plan says the image is `fbl_v2b`, "199/199 equivalence" (`docs/plan_diffcotune_2026-11-11.md:124`). Not stated in any file I read: that the bindings and `~/Desktop/fbl_v2b_firmware` are byte-identical (that directory is not a git repository).
- **Bindings in use:** `frsim.__file__` = `~/Desktop/flying_robot_course_fbl/simulator/frsim/__init__.py`; `frsim/firmware.py:load()` inserts `config.firmware_build_dir()` = `simulator/_build/crazyflie-firmware/build` (built 10 Nov 18:55) at the front of `sys.path`. It contains the FBL fields (`fbl.c_d`, `nn_en`, `abg_on_new`, `inner` found in `cffirmware.py`). `~/Desktop/crazyflie-firmware/build` (25 Oct) is a different `.so` (cmp differs) and is what `lab/preflight.py` import-checks; frsim does not use it. **No binding build is needed for FBL.**
- **Loop timing in frsim:** `simulator/frsim/episode.py:167` calls the FBL firmware on every 1 ms tick (S0-S3 on every second tick); the mixer output is queued only on even ticks (`episode.py:169-171`), delay 4 ms. **Measured in this stage** (`fbl/diag_law.py`, model commands fed with frsim states vs the firmware's motor commands): the controller state (alpha-beta-gamma estimator, position integral, yaw set point, rate-PID integrators) advances only on the even ticks with dt = 2 ms; the odd-tick call changes no state. With one step per 2 ms, dt 2 ms, the model's commands equal the firmware's to at most 2 counts (6e-6 N) on FIG8, so FBL in frsim behaves as a 500 Hz controller exactly like the old 500 Hz torch copy assumed. The host source (`firmware/host/oot_host.c:337-341`: +2000 us per `usecTimestamp()` call, first call dt 0, `controller_omar_indi.c:221`) does not by itself explain why the odd calls do not advance the state; not traced further.
- **Switches for the 4 variants:** firmware fields `fbl.dw_en` (whole downwash residual, ROM + network, on/off; firmware default 1, `controller_omar_indi.c:89`) and `fbl.nn_en` (network on/off; with 0 the residual is ROM only, `:260`). `frsim/controllers.py:configure` sets `nn_en = 1` and does not touch `dw_en`; there is no variant argument in `EpisodeConfig`/`Controller` (`controllers.py:83-84`). So in frsim today: ROM + net (dw_en 1, nn_en 1) only. Base (dw_en 0) and ROM-only (dw_en 1, nn_en 0) exist in the firmware and need only a change in `configure` (a simulator patch). "Net only, no ROM" has **no firmware path** (`dw_en` switches both together) and no weights file for it was found; `docs/fbl/STATUS.md:36` lists "net only, 9 neurons" as an offline fit result (R² 0.41), not as a deployed network.
- **Mass, inertia:** `frsim/config.py:24-27`: mass 0.0427 kg, inertia diag(16.571710e-6, 16.655602e-6, 29.261652e-6) (Omar values). `controllers.configure` sets the controller inertia `fbl.J` to the same values (`controllers.py:123-127`); the firmware default is 2.395e-5 / 2.395e-5 / 3.235e-5 (`controller_omar_indi.c:91`) and is overridden.
- **Inner loop, C_D, net:** `inner = 1` (stock rate PIDs inside FBL), `abg_on_new = 0`, `nn_en = 1`, `c_d = 0.55` (`controllers.py:129-132`; firmware default c_d 0.43). Net: 4 hidden neurons, weights in `fbl_nn_weights.c` ("knode_s0977_h4.pth, tag knode_s0977_h4_cd0.55"); the same numbers are the `NN` dict in the old torch copy `lab:experiments/tuning/diff/fbl_plant_torch_v2o.py`.
- **Gains:** 6 tuned (`controllers.py:19`), preset 1 = `FBL_DEFAULT_GAINS` (`controllers.py:36`): kp_xy 14.0, kv_xy 9.5, ki_xy 12.0, kp_z 11.25, kv_z 5.4, ki_z 12.0. Fixed `FBL_FIXED` kr_xy 59.5, kr_z 35.0 (`:38`); they are set in the firmware but unused with `inner = 1` (`crazyswarm2` yaml comment: "the rate gains of preset 1 are unused with inner 1"). Crash tilt for FBL 45 deg (`config.py:54`).
- **Sensors:** `sensors.Sensors(seed, plant, variant, controller.tree, noise)` takes the tree flag (noise handling for FBL differs from the tree: `frsim/sensors.py`; not read in detail yet).
