**Here is the complete, clear explanation** of the Tal & Karaman INDI controller as implemented in this project. The core four equations follow the paper exactly. Two implementation details are adjusted for the Crazyflie hardware: the angular acceleration measurement uses a two-stage filter chain (Butterworth pre-filter on the gyro, then first-order IIR on the derivative), and the torque base for the increment uses the actual current torque estimated from per-motor RPM measurements rather than the previous command.

**Primary reference**: E. Tal and S. Karaman, "Accurate Tracking of Aggressive Quadrotor Trajectories using Incremental Nonlinear Dynamic Inversion and Differential Flatness," arXiv:1809.04048v2, 2020. All equation numbers below refer to this paper.

---

The INDI controller combines feedforward signals from the desired trajectory with real sensor measurements to achieve accurate, robust tracking of aggressive maneuvers. All noisy or differentiated measurements are passed through low-pass filters before being used in the control law.

### 1. Desired angular acceleration from the trajectory (feedforward)

From the desired position trajectory and its fourth derivative (snap), differential flatness is used to compute the **desired angular acceleration** the vehicle should have at each moment. This value is called **α_des**.

**α_des** ← computed from trajectory snap via differential flatness.

> **Paper reference**: Tal & Karaman **Eq. (15)** gives the angular acceleration reference Ω̇_ref directly from snap **s_ref** and yaw acceleration **ψ̈_ref**. Eq. (14) gives the accompanying angular rate feedforward Ω_ref from jerk **j_ref**. Both use the rotation matrix **R** and the angular-rate-to-yaw-rate matrix **S** (Eq. (12)) as derived in Section II-B.
> Notation map: Ω̇_ref (paper) = α_des (this doc); Ω_ref (paper) = ω_d (this doc).

This is a reference signal generated by the planner. No filtering is applied to α_des itself. When the planner does not provide snap (e.g. position-only setpoints), α_des = 0 and the controller operates in pure-feedback mode — still robust due to the α_meas cancellation in equation 4.

### 2. Total desired angular acceleration command

The controller blends the feedforward term with feedback on attitude and rate errors:

**α_ref = α_des − K_R e_R − K_ω e_ω**

> **Paper reference**: Tal & Karaman **Eq. (28)**:
> &nbsp;&nbsp;&nbsp;&nbsp;**Ω̇_c = K_ξ ξ_e + K_Ω (Ω_ref − Ω_f) + Ω̇_ref**
> Notation map: Ω̇_c = α_ref, Ω̇_ref = α_des, K_ξ = K_R, ξ_e = e_R, K_Ω = K_ω, (Ω_ref − Ω_f) = e_ω.
> The attitude error ξ_e is computed via Eq. (27) from the incremental attitude command ξ_c (Eq. (26)), itself derived from Eqs. (22)–(25).

**Legend:**

- **α_ref**: total desired angular acceleration command (rad/s²)
- **α_des**: feedforward angular acceleration from trajectory snap (rad/s²)
- **K_R**: attitude gain matrix (positive definite, diagonal) with units **1/s²**; closed-loop attitude bandwidth ωₙ = √K_R
- **e_R**: attitude error on SO(3) = ½(R_d^T R − R^T R_d)^∨ (rad)
- **K_ω**: angular rate gain matrix (positive definite, diagonal) with units **1/s**; damping ratio ζ = K_ω / (2ωₙ)
- **e_ω**: angular rate error = ω − ω_d (rad/s), where **ω_d** is the desired body angular rate computed from trajectory jerk via differential flatness (feedforward)

Both e_R and e_ω are computed from filtered sensor data (attitude from the state estimator and filtered gyroscope rates).

### 3. Measured angular acceleration (the most important filtered signal)

The drone does not have a direct angular acceleration sensor. It computes **α_meas** from the gyroscope using a **three-stage chain**:

> **Paper reference**: The filter chain corresponds to the LPF blocks H(s) applied to Ω to obtain **Ω_f** and **Ω̇_f** shown in **Fig. 4** (red area) and analysed in **Section III-D** (text before Eq. (29)) and **Section IV** (transfer function H(s) in Eqs. (44)–(45)). The Butterworth parameters — second-order, cutoff 188.5 rad/s (30 Hz) — are given in **Table III**. There is no single equation for the multi-stage chain; it is captured by H(s) throughout the paper.
> Notation map: Ω_f (paper) = ω_filtered (this doc); Ω̇_f (paper) = α_meas (this doc).

**Stage 1 — Butterworth pre-filter on raw gyro:**

```
ω_filtered[k] = Butterworth2( ω_raw[k] )
```

Removes high-frequency vibration and broadband sensor noise from the gyro signal before any differentiation is performed. A second-order Butterworth filter is used here because its maximally-flat passband preserves the true angular rate signal while strongly attenuating motor vibration frequencies.

**Stage 2 — Finite difference to obtain raw angular acceleration:**

```
α_raw[k] = (ω_filtered[k] − ω_filtered[k−1]) / Δt
```

**Legend:**

- **α_raw**: unfiltered angular acceleration from finite difference of the pre-filtered gyro (rad/s²)
- **ω_filtered[k]**, **ω_filtered[k−1]**: Butterworth-filtered body angular velocity at current and previous sample (rad/s)
- **Δt**: control sample period (s)

**Stage 3 — First-order IIR post-filter on the derivative:**

```
α_meas[k] = k · α_raw[k] + (1 − k) · α_meas[k−1]
```

**Legend:**

- **α_meas[k]**: filtered measured angular acceleration at sample k (rad/s²) — the key real-world measurement used in the control law
- **α_raw[k]**: raw finite-difference angular acceleration from stage 2 (rad/s²)
- **α_meas[k−1]**: filtered output from previous sample (rad/s²)
- **k**: filter gain (dimensionless), **k** = Δt / (Δt + RC), RC = 1 / (2π · f_c)
- **f_c**: post-filter cutoff frequency (Hz); can equal the Butterworth cutoff or be set independently

The two-stage filter design (Butterworth on raw ω, then IIR on α_raw) is motivated by two distinct noise sources: motor-vibration contamination of the gyro signal (removed by the pre-filter before differentiation) and differentiation-amplified noise in the transition band (further attenuated by the post-filter). The total effective filter on the raw gyro derivative is the cascade of both stages.

This filtered **α_meas** is what makes INDI robust: it contains the true physical effects (including disturbances and gyroscopic terms) at the current moment, so any effect that external disturbances have on the attitude dynamics is already visible in **α_meas** and is automatically rejected by the increment **δτ** in equation 4.

### 4. Incremental torque command (the core INDI law)

The controller calculates how much extra torque is needed to reduce the acceleration error:

**δτ = J (α_ref − α_meas)**

The new torque command sent to the motors is:

**τ_new = τ_current + δτ**

> **Paper reference**: Tal & Karaman **Eq. (31)**:
> &nbsp;&nbsp;&nbsp;&nbsp;**μ_c = μ_f + J (Ω̇_c − Ω̇_f)**
> This is derived in Section III-D by rewriting the rotational dynamics **Eq. (4)**: Ω̇ = J⁻¹(μ + μ_ext − Ω × JΩ), estimating the external moment **μ_ext** from measured motor speeds and filtered angular rate via **Eq. (29)**: μ_ext = JΩ̇_f − μ_f + Ω_f × JΩ_f, then substituting into Eq. (4) to obtain the increment in **Eq. (30)**–**(31)**.
> Notation map: μ_c = τ_new, μ_f = τ_current, J(Ω̇_c − Ω̇_f) = δτ.

**Legend:**

- **δτ**: incremental torque correction (Nm)
- **J**: inertia matrix (diagonal, J_xx, J_yy, J_zz in kg·m²). Note: this is equivalent to the Smeur formulation with g1 = 1/J — when g1 = 1/J the expressions δτ = J·α_err and δτ = α_err/g1 are identical.
- **α_ref**: desired angular acceleration from equation 2 (rad/s²)
- **α_meas**: filtered measured angular acceleration from equation 3 (rad/s²)

**Legend for τ_new:**

- **τ_new**: torque command sent to the motor mixer (Nm)
- **τ_current**: current body torque estimated from per-motor RPM measurements (Nm) — see below
- **δτ**: incremental correction from above (Nm)

**τ_current from RPM measurements:**

Rather than using the previous torque command (which does not account for motor response lag), τ_current is estimated from the actual motor state measured by the RPM deck:

```
F_i       = k_T × RPM_i²
τ_current = allocation_matrix × [F_1, F_2, F_3, F_4]
```

> **Paper reference**: Tal & Karaman **Eq. (5)**:
> &nbsp;&nbsp;&nbsp;&nbsp;**[μ; T] = G₁ ω^{∘2} + G₂ ω̇**
> where G₁ (Eq. (6)) is the allocation matrix mapping motor speeds squared to torque and thrust, and ω is the vector of four motor speeds. The G₂ term (Eq. (7)) is the gyroscopic contribution from rotor inertia, which is neglected in our Crazyflie implementation due to the small rotor moment of inertia J_r. In our notation: μ_f = G₁ ω_f^{∘2} (using low-pass-filtered motor speeds, as in Eq. (5) with the subscript f).

**Legend:**

- **F_i**: thrust force of motor i (N)
- **k_T**: motor thrust constant (N / RPM²), identified on a thrust stand before first flight
- **RPM_i**: measured rotational speed of motor i (rev/min), from the RPM deck
- **allocation_matrix**: maps per-motor forces to body torques (τ_x, τ_y, τ_z) based on arm geometry and spin directions (kg·m)
- **RPM deck**: hardware requirement — the Crazyflie RPM deck must be fitted and k_T must be bench-identified before activating Mode 1 INDI

**In simulation** (where no RPM deck exists): τ_current is approximated by **τ_prev_command**, the torque command from the previous control cycle. At 500 Hz the motor response lag is small relative to Δt, making this a valid approximation for simulation validation.

| 2 | **α_ref = α_des − K_R e_R − K_ω e_ω** | **Eq. (28)** | Blend feedforward with attitude/rate feedback |

This is the complete, minimal core of the INDI controller as implemented in this project. Everything else (SO(3) attitude representation, outer position loop, gyroscopic feedforward at the mixer) supports these four equations.

### External forces (f_ext)

The outer translational loop includes unknown external force terms **f_ext** (aerodynamic drag, wind, ground effect). The inner INDI loop does not need an explicit model of **f_ext**. Because INDI works on measured angular acceleration, any effect that **f_ext** has on the attitude dynamics is already visible in **α_meas** and is therefore rejected automatically by the increment **δτ**. This is one of the main practical advantages of the design: you do not need to model **f_ext** accurately; the controller sees its effect through the sensors and corrects for it every cycle.

> **Paper reference**: Tal & Karaman **Eq. (18)**: f_ext = m(a_f − (τb_z)_f − gi_z) — the external force is estimated from measured linear acceleration and specific thrust. The analogous derivation for the angular channel gives Eq. (29) for μ_ext, leading directly to the INDI increment in Eq. (31). Section IV-A (Eqs. (44)–(45)) shows analytically that INDI fully rejects disturbance moments, while a non-incremental controller cannot.

### Filter cutoff frequency guidance

The cutoff frequencies of both filter stages are key tuning parameters. The Butterworth cutoff and the IIR post-filter cutoff can be set independently or to the same value.

- **Too high**: noise enters the control loop via α_meas, causing high-frequency oscillations
- **Too low**: phase lag in α_meas makes the INDI loop sluggish or unstable

Typical starting point: **50–80 Hz** for both stages at 500 Hz control rate. The Butterworth cutoff is more critical (it directly shapes the pre-filter applied to gyro noise); the IIR cutoff provides a secondary tuning knob.

> **Paper reference**: Tal & Karaman use 30 Hz (188.5 rad/s) second-order Butterworth (**Table III**). Their platform is heavier with stronger motors; our Crazyflie 2.x operates at 500 Hz so a higher cutoff (50–80 Hz) is appropriate to avoid excessive phase lag at the faster control rate.

### Hardware prerequisites for Mode 1 INDI

Before activating INDI (Mode 1) on real hardware:

1. **RPM deck fitted** on the Crazyflie
2. **k_T identified** on a thrust stand: apply known PWM steps, measure thrust, fit k_T = thrust / RPM²
3. **Allocation matrix verified**: confirm motor spin directions match the firmware's assumed layout
4. **Gains for a first hover test**: start with conservative KR (ωₙ ≈ 10–15 rad/s) and KW (ζ ≈ 1.4) — raise gradually once hover is confirmed stable
