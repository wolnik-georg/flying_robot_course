## 1. What happened, in order

2. **Diagnosis.**
   - cflib could start logging on both drones (≈ 880 kB each), but CS2 could not.
   - `usd_cs2_diag.sh`: every runtime set (usd, `led.bitmask`) was accepted and published, but the server never forwarded it. Same with the May binary and a fresh build.
   - Lab PC ROS history: `apt upgrade`, `apt remove ros-*` and a reinstall on 11 Nov; GUI updater again on 20 Nov 16:20. Done by someone outside the team.
3. **Root cause narrowed (planning agent, Docker `ros:jazzy`, the lab PC's exact versions).** The real server works there, so the cause is specific to the lab PC: the server never receives its own parameter events.
4. **Fix: crazyswarm2 `71219f3`.** Forward on set (post-set callback), not via the server's own events. On main and all 11 `study_*` branches. Applied with `apply_runtime_param_fix.sh`.
