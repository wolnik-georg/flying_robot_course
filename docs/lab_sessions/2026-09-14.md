**uSD timing bug, root-caused and fixed (desk time).** Each drone's `usecTimestamp()` free-runs
from its own power-on with no shared reference, so uSD log timestamps carried a constant
per-drone offset. Stock firmware already exposes the fix as a broadcastable param
(`usec_time.c`'s `usec.reset`, documented upstream for exactly this: UAV time sync) — we were
just never calling it. Added `allcfs.setParam("usec.reset", 1)` as its own broadcast right
before the uSD-logging-start broadcast in `formation_flight.py`, mirrored in
`flight.py`/`simple_flight.py` (`crazyswarm2` `932d901`). Not yet flight-tested — worth
confirming today's uSD sync check actually shows a tighter offset than before.

**NA-INDI faithful port, implemented and numerically verified (desk time, before lab).**
Supervisor judged the residual oscillation unacceptable as a known limitation; decided to port
Cobo & Briesewitz's `controller_lee.c` bit-for-bit rather than keep iterating on our own INDI.
New, fully independent controller slot `stabilizer.controller=7` (`ControllerTypeOot2`),
alongside the existing `=6` — separate enum, dispatch row, Rust module
(`firmware_app/src/naindi.rs`), no shared state. Required one further local
`crazyflie-firmware` change (`sensorData_t.gyroNoLpf`, ported verbatim) so the port reads the
exact same unfiltered gyro the reference does. **Numerically verified against the reference's
own compiled C**: 5 hand-picked non-trivial states match thrust and torque to ~1e-9. Exactly 4
documented, physically/architecturally necessary deviations; everything else identical. Builds
clean on all three platforms. Switchable via a plain `controller: 7` in `crazyflies.yaml`, same
as any other controller. **Never flown.** Full record: `flying_drone_stack` `4fbe013`+`c089511`
+`95182f1`, `firmware_app/host/naindi_reference_build_notes.md`.

**Neural-Swarm2 exact-architecture port, implemented (desk time, before lab) — does not fit in
RAM, and is not to be fixed by touching the network.** `residual_nn.rs` replaced with a direct
