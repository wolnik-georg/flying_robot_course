## 1. What happened, in order

1. Pulled and flashed the `e_R` logging + analysis pipeline. Bench checks passed.
2. **First hover crashed.** Geometric, `ctrl_mode=0`: roll std 24.8°, peaks ±82°, ~1.23 Hz
   limit cycle. A second attempt behaved the same.
3. **First hypothesis — `kr_geo` firmware default.** Found `g_indi_kr_geo = 100.0f` in
   `traj_iface.c` where the geometric law needs `0.010` **Nm** — 10,000× too large, the
   same unit confusion the 2026-09-07 session caught in the yaml but which was never fixed
   in the firmware default. Fixed. **This turned out NOT to be the cause** (the yaml was
   supplying the correct value all along), but it is a real latent bug: a failed param write
   would have meant a 10,000× attitude gain.
4. **Found a second latent bug while verifying:** gain selection used `if mode == 0` while
   the branch consuming it is `if mode & 2 != 0 … else`. `ctrl_mode=1` (position INDI, which
   keeps a *geometric* attitude loop) would have been handed INDI's `kr=2400` in an Nm-unit
   law — ~240,000× torque, instant crash. Never flown at mode 1. Fixed to `mode & 2 == 0`.
5. **Log-metadata gap identified.** `flight.py`'s meta block records a hardcoded key list
   predating `kr_geo`/`kw_geo`/`clamp_en`, so a geometric flight's log said only
   `indi_kr=2400` — the INDI gain `ctrl_mode=0` never uses. Nothing in the log said which
   attitude gains actually flew. Added a full `firmware_params` dump appended into the CSV
   itself (`# meta:full_*`). **This is what made the rest of the session solvable.**
6. **`clamp_en` read 0, not 11** — from a stale *installed* `crazyflies.yaml`
   (`get_package_share_directory`), while the source tree said 11. Torque telemetry
   confirmed the consequence: `tau_x/tau_y` reached **0.244 Nm**, ~5× the documented
   0.052 Nm blow-up threshold, with no clamp to stop it. Rebuilt the `crazyflie` package.
7. **Ran the stock controllers as a vehicle sanity check.** Stock Lee (`controller=5`):
   roll std **0.74°**, peak 5.2°, clean 25 s hover. Stock INDI (`controller=3`): crashed,
   std 18.0°. Vehicle confirmed healthy; the failure is in the control software.
8. **Second hypothesis — the mid-air controller handover — RAISED AND THEN REFUTED.**
   `simple_flight` switches from the ramp config to the trajectory config at t≈6.06 s, and
   every divergence began exactly there. But `flight.py` is **byte-identical** between
   `main` and `finalized-version-for-INDI-project` (same blob `4eaa7f6`), and the brushless
   flew the same `ctrl_mode 0→3` handover with the same `40/8 → 64/5` gain change through
   late July successfully. A change was briefly made to remove the handover; it was
   **reverted** once the diff showed the handover was not the regression.
9. **Root cause 1 — geometric ran INDI's position gains.** `kp_xy=64/kv_xy=5` (ζ=0.31) are
   INDI's locked block, tuned 2026-07-19 against `kr=2400/kw=170`. Geometric's attitude loop
   is far slower (`kr_geo=0.010`, the 27 g platform's value on a 41 g airframe), so the
   cascade separation those gains assume does not hold. Roll rings up ~1.45×/s:
   2.2 → 3.1 → 4.9 → 7.2 → 13.3 → 20.1 → 29.4°. Confirmed by `# meta:pos_kv_xy=5.0` in both
   09-07 geometric logs. Geometric now selects `40/8` (the yaml's own named alternative, and
   the ramp config that flew cleanly in every flight this session).
10. **Root cause 2 — the residual sign flip.** `fa2131a` (2026-08-23) changed the position
    loop from `.add(a_indi)` to `.sub(a_indi)`; every `ctrl_mode=3` flight since crashed.
    Not just a thrust term: `f_d` → `thrust_vec` → `desired_rot()` → `Rd` → `eR`, so it moves
    the **commanded attitude** — measured at 8% of hover thrust. Parked at the frozen `+1`
    behind a new runtime param `indi_gains.res_sign`; the fix is preserved, not deleted.
11. **Root cause 3 — the landing bug.** `simple_flight` streamed 2.5 s of `cmdFullState`
    then called `land()`. `flight.py`'s own docstring: *"cmdFullState forces low-level mode;
    HLC land()/goTo() do not work afterward."* The vehicle never descended and `arm(False)`
    cut motors from ~0.7 m. Removed; the sequence is now plain `figure8.py`.
12. **Reverted every remaining unflown control-law delta** to frozen: `frame_conv` 1→0
    (Faessler), residual net no longer evaluated every tick, RPM guard re-gated to
    `mode != 0` (so INDI inherits a cold `rpm_prev` at handover, as frozen did).
13. **Independent audit run** against the code, git history, logs and the compiled
    controller — brief in [`../REVIEW_REQUEST_2026-09-09.md`](../REVIEW_REQUEST_2026-09-09.md),
    findings in [`../REVIEW_FINDINGS_2026-09-09.md`](../REVIEW_FINDINGS_2026-09-09.md).
    Claims A, C, D, E, F, G **confirmed**; Claim B **downgraded to UNPROVEN attribution**
    (the 09-07 flash carried three unflown deltas at once — sign flip, rnn-every-tick, RPM
    guard — and the radio logs cannot distinguish them; all three are reverted, so the
    fix-set is complete regardless). Three further defects found and fixed:
    - **N1** — `alpha_ref` used the mode-selected `kr_geo` (an Nm torque gain) instead of
      INDI's `kr`, changing filter warm-up across a handover. The one unlisted frozen-delta.
    - **N2** — future geometric logs would carry contradictory pos-gain metadata
      (`pos_kv_xy=8.0` vs `full_pos_gains_kv_xy=5.0` in the same file).
    - **N3** — the rnn gating had eliminated the *predict-and-log-only* state the thesis's
      predicted-vs-measured evaluation depends on. Compute now gated on `ready` alone.
14. Added `experiments/analysis/check_flight.py` — one-command pass/fail verdict per flight,
    validated against both known outcomes (geometric crash → FAIL, Lee clean → PASS).
