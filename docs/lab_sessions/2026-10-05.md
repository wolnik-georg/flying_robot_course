## 8. Insights (for the thesis and the next session)
1. The crashes that looked like a network problem were operational: identical marker patterns let the tracker give one drone the other's pose (trigger unknown), and the top drone's battery collapsed to 2.5 V (its markers/link die; in A1 it fell onto cf5). With healthy batteries, 3 of 3 A8 flights were clean.
2. The 100 Hz network is a good residual predictor on hardware (corr 0.85-0.92; A1 stack -1.61 vs measured -1.60 m/s^2), so neighbour broadcasting and the weights path work.
3. The controller adds the network term with the same `res_sign=+1` as INDI (documented reinforcing): crossing dips -10.9 cm (network on, 16 crossings) vs -5.9 cm (off, 8), non-overlapping, and the measured residual is not larger with the network on => sign, not disturbance. Baseline ~6 cm per ~0.6 m/s^2 predicts ~12 cm with the wrong sign: matches.
4. Readiness gate for the comparative study: see `docs/next_steps_checklist.md` (sign test on A8 + A1, A1 oscillation attribution, no over-compensation, scenario set, operating rules).
5. Process lessons: record a pose bag every session; check `vbat` min in the radio CSV after each flight; copy cf_second's card before swapping; a 0-byte uSD log after a crash is consistent with power loss.
